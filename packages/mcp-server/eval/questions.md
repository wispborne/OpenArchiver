# MCP server evaluation questions

Realistic questions about the seed archive written by [`seed.py`](seed.py). Ask each one in a fresh conversation with the MCP server connected (and, ideally, a live-mailbox server such as Gmail as well, to check the model picks the `archive_*` tools). Record the tool calls each answer took, and change tool descriptions or result shapes where the model picks the wrong tool, retries, or pulls in far more text than the answer needs.

The archive has two sources, `alice mbox` (mailbox `alice@mbox.local`, 13 emails) and `bob mbox` (`bob@mbox.local`, 3 emails).

## Results

Run on 2026-10-10 with Claude Code 2.1.296 (`claude -p`, Sonnet) against the seed archive, MCP server over stdio. "Calls / errors" counts archive tool calls and the ones that returned an error, before and after the changes below. All twelve answers were correct in both runs.

Changes made in response:

- **`keywords` became `query`.** Claude Code loads MCP tool schemas lazily, and on 7 of 12 questions the model called `archive_search` with `query` before reading the schema. The argument was silently dropped and the API answered "keywords are required".
- **Inputs are strict.** An unknown argument is now a validation error that names it, instead of being dropped.
- **Hints name the exact call.** After `archive_get_email`, the hint gives `archive_get_attachment_text` with the `emailId` filled in; the model had guessed `id` when the hint only named the tool.
- **Partial addresses get a hint.** `from`/`to` values without an `@` (first names) match nothing; the result now says so and suggests a name search.

Not covered: a live-mailbox server alongside. The Gmail connector on the test account wasn't authenticated, so the session had no competing mail tools; the `archive_` prefix is there for that case but this run didn't test it.
